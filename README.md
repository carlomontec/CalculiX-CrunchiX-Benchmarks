# CalculiX CrunchiX Benchmarks

Benchmark models, results, verification reports and studies for the
CalculiX CrunchiX (ccx) finite element solver, built from the
[CalculiX CrunchiX MultiSolver](https://github.com/carlomontec/CalculiX-CrunchiX-MultiSolver)
edition and compared with official CalculiX releases by Guido Dhondt.

The aim is measured, reproducible evidence: how long each linear solver takes
and how much memory it needs on real machines, whether the solvers agree, and
whether a build gives the same answers as upstream. It is meant to help any
CalculiX user choose a solver, size a machine or check a build. The models are
chosen to stress the solvers, not to show what CalculiX can model.

| Repository | Holds |
|:---|:---|
| [CalculiX-CrunchiX-MultiSolver](https://github.com/carlomontec/CalculiX-CrunchiX-MultiSolver) | Source code, build system and the official test suite |
| **CalculiX-CrunchiX-Benchmarks** (this one) | Benchmark models, the runner, results and reports. No solver source code. |

## Layout

```
models/<model>/           input deck, mesh generator (remesh.py) and README
runner/run_benchmark.py   runs a model with each solver and thread count
results/<model>/<date>_<machine>_<mesh>/
                          one published benchmark run: results.json, run.json, README.md
releases/<release>/       verification of a release against official CalculiX
upstream-merges/<date>/   test-suite reports for merges of upstream CalculiX
json-export/<date>_<topic>/
                          reports on the JSON result export
studies/<topic>/          longer write-ups
tools/build_index.py      generates the tables in this README and the
                          README of each benchmark run
```

Every result folder has a `run.json` that records what was run, on which
machine, with which version of the code and with which command. Values that
were not recorded at run time are `null`, never estimated.

## Reading the benchmarks

- **Wall time** is the elapsed time of the whole ccx run, measured by the
  runner. **Peak memory** is the peak resident set size of the ccx process.
- **Threads** is `OMP_NUM_THREADS` (and the solver's own thread setting).
- **Agreement** compares quantities computed by every solver (tip
  displacements, effective modal masses) against one reference solver. It
  shows that a faster solver gives the same answer, not that the answer is
  physically right.
- Timings depend on the machine, the operating system, the BLAS/LAPACK
  library and the build options. Compare runs on the same machine first.

## Running a benchmark

See [models/README.md](models/README.md). In short, with a MultiSolver
checkout next to this repository:

```bash
python3 runner/run_benchmark.py --case naca_blade --level fine --threads 1 2 4 8
```

## Adding results

1. Run the benchmark with
   `--out-dir results/<model>/<date>_<machine>_<mesh>` and rename the output
   to `results.json`.
2. Write `run.json` next to it (copy one from another run of the same model
   and update every field).
3. Run `python3 tools/build_index.py` and commit the folder together with the
   regenerated README files.

[AGENTS.md](AGENTS.md) has the full conventions.
